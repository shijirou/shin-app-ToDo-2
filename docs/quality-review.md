### 全体の評価
アプリ全体のつくりは、React・Spring Boot のふつうのやり方にそっています。大きく外れている所はありませんでした。
- **よい所**: 画面・API・DB の役割分け、Controller → Service → Repository の流れ、DTO で返している（エンティティをそのまま返していない）、入力チェック（`@Valid`）、`@Transactional`、ドラッグ&ドロップの楽観的更新と、失敗したときに元へ戻す処理、TypeScript の型。
- **弱い所**: エラーの返し方の細かい所、日本語入力や使いやすさへの配慮、テストの少なさ。

### 標準のやり方から外れていた所 → 修正済み

| # | 場所 | 内容 | どうしたか |

| 2 | `ListService.getBoard` | ボードを読むと、リスト一覧で1回＋リストの数だけカードを読む SQL が走っていた（N+1 問題。リスト3つで4回） | `@EntityGraph` で、リストとカードを1回の SQL で読むようにした（4回 → 1回） |
| 3 | `Card`（cards テーブル） | 外部キー `list_id` に索引がなかった（PostgreSQL は自動では作らない） | 索引 `idx_cards_list_id` を付けた。カードが増えても「このリストのカード」を速く探せる |

### 問題なしと判断したもの（理由つき）
- **SpotBugs EI2（`CardController`・`ListController`）**: Spring がサービスを渡す「コンストラクタ注入」への指摘。Spring でいちばんすすめられている書き方なので問題なし。
- **SpotBugs EI（`TaskList.getCards()`）**: JPA のエンティティが中のカードの一覧を返すのはふつうの書き方。使っているのはサービス層の中だけ。
- **lint の行単位の無効化（3か所）**: モーダルの暗い部分と「…」メニューの外側の見えない幕は、マウス専用の「外を押したら閉じる」部分（キーボードでは Esc や「…」ボタンで閉じられる）。`role="dialog"` は下の「今後の改善」の `<dialog>` を参照。どれもコメントに理由を書いた。
- **Gradle の「古い機能を使っている」警告**: SpotBugs の Gradle プラグインから出ているもので、このアプリのコードではない。

### 今後の改善（今は困らないが、大きくしたいときに直す）

| # | 内容 | なぜ | どうするか |
|---|---|---|---|
| 1 | **テストが「起動できるか」の1つだけ**。しかも DB を起動していないと失敗する | 直したときに、ほかを壊していないか自動で確かめられない。いちばん大きな改善点 | サービスのテスト（並び替えの計算など）、`@WebMvcTest` で API のテスト、Testcontainers（テストのときだけ DB を自動で起動する道具）を入れる |
| 2 | 表を `ddl-auto=update`（Hibernate の自動作成）で作っている | 列の削除・名前の変更はできず、どう変えたかの記録も残らない | Flyway（表の変更を SQL ファイルで順番に管理する道具）を使うのがふつう |
| 3 | モーダルが `<div role="dialog">` | Tab キーで、モーダルの後ろの画面に移れてしまう | HTML の `<dialog>`（`showModal()`）に変える。`autoFocus` の代わりに、開いたあとで入力欄にカーソルを置く処理が必要 |
| 4 | ドラッグ&ドロップがマウス専用 | 要件（非機能要件）どおりだが、dnd-kit は読み上げソフトに「スペースで持ち上げる」と案内するのに、キーボードでは動かせない | dnd-kit の `KeyboardSensor` を足す（カードの Enter＝編集と、ぶつからないようにする） |
| 5 | ドラッグを続けて速く行うと、1回目の保存のあとの読み直しが、2回目の画面の動きを一度上書きすることがある | 最後は DB の内容にそろうので壊れはしない | 読み直しを最後の1回だけにする、または TanStack Query のようなデータ取得の道具を使う |
| 6 | エラーの形が自分で決めた `{"message"}` | 今の画面にはこれで十分。Spring には標準の形 ProblemDetail（RFC 9457）もある | API をほかの人にも使ってもらうときは、標準の形を検討する |
| 7 | DB のパスワードを `application.properties` に直接書いている | 自分のパソコン専用なので今は問題ない | インターネットに公開するときは環境変数で渡す |
| 8 | 同時に2つの画面で同じカードを変えると、あとの保存が勝つ | 1人で使う前提なので今は問題ない | `@Version`（楽観ロック）で、ぶつかったことに気づけるようにする |
| 9 | カードの内容に長さの上限がない（DB は TEXT） | 1人で使う前提なので今は問題ない | `@Size` と画面の `maxLength` で上限を決める |
| 10 | リポジトリ直下にプロトタイプ（`index.html`・`style.css`・`app.js`）がある | 本物の画面（`frontend/`）とまちがえやすい | `docs/prototype/` などに移す |
| 11 | `package.json` の版の範囲の下限が、入っている版より古い（例: `oxlint ^1.81.0` で 1.88.0 が入っている） | `package-lock.json` で実際の版は固定されているので動きは同じ | 版を上げるときに、下限もそろえる |
